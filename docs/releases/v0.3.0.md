# Kas Will v0.3.0

- Check-in renewal is now a single guided flow: one click builds the transaction, shows the fee, takes the wallet password, signs and broadcasts, then waits for the node to confirm before resetting the countdown. Renewal rejections (expired or already spent) are explained bilingually instead of an English-only error.
- Node operations are dramatically faster: the local service keeps one warm wRPC connection per network and pre-warms TN10 at startup (previously every request re-ran resolver discovery, worst case ~40 s).
- Every long-running action shows a live progress card with the current step; mutating operations run one at a time, so duplicate clicks can no longer double-spend.
- The wallet page gains KAS send (build → review fee → password → broadcast) and experimental KCC20 support: register a token once by pasting the issuer descriptor plus the current redeem program, see advisory Kascov balances, and send KCC20 to any P2PK address with the current cell verified against the node's P2SH script hash. The KCC20 will-creation form can fill its fields from a registered token.
- Portable operation packages follow the covenant automatically: a record imported on another device accepts renewals and distribution spends of the currently live cell even when its stored outpoint lags behind — import once, never re-export after renewals.
- Operated (deployed) wills can be deleted locally through a strict two-step confirmation (fresh package backup with a manually chosen save location each time, then typing `DELETE LOCAL WILL RECORD`); the service independently verifies the typed phrase and a commitment matching the current portable package.
- The check-in & claim countdown now shows days plus `HH:MM:SS`, ticks every second, and auto-refreshes at maturity.
- New Kaspa-style app icon across every platform package and the web favicon.
- Mainnet transactions remain disabled. TN10 experimental only.

# Kas Will v0.3.0（中文）

- 签到续期改为一键引导流程：点击后自动构建交易、显示手续费、输入钱包密码、签名并广播，等待节点确认后才重置倒计时；续期被拒（已到期/已支出）时会用中文说明原因。
- 节点操作大幅提速：本地服务按网络保持常驻 wRPC 连接并在启动时预热 TN10（此前每个请求都重新走 Resolver 发现，最差约 40 秒）。
- 所有耗时操作显示带当前步骤的实时进度卡片；变更类操作同一时间只允许一个，重复点击不会再造成双花。
- 钱包页新增 KAS 发送（构建 → 核对手续费 → 密码 → 广播）与实验性 KCC20 支持：粘贴发行方 descriptor 和一次当前 redeem program 即可登记代币，显示 Kascov 参考余额，向任意 P2PK 地址发送 KCC20 前会用节点 P2SH 脚本哈希验证当前单元；创建 KCC20 遗嘱时可直接选择已登记代币。
- 便携操作包自动跟随 Covenant：其它设备导入的记录即使本地输出点落后，也接受花费当前活跃单元的续期与分配——导入一次，续期后无需重新导出。
- 操作过（已部署）的遗嘱可通过严格两步确认从本机删除（每次手动选择位置另存新备份 + 输入 `DELETE LOCAL WILL RECORD`）；服务端独立校验短语与匹配当前操作包的承诺。
- 签到与提取页倒计时改为“X 天 HH:MM:SS”按秒刷新，到期自动刷新状态。
- 全新 Kaspa 风格应用图标，覆盖全部平台安装包与网页 favicon。
- 主网交易保持关闭，仅限 TN10 实验使用。
